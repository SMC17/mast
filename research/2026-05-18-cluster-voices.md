## Three convergent claims (synthesis)

1. **Parallelism is the unit, not the agent.** Karpathy, Yegge, Cherny, Osmani, Hashimoto, Ronacher, and the Spotify/Docker teams all explicitly converge on the same lemma Steinberger ships in the wild: a single agent is a toy, a *fleet* is the substrate. Yegge calls it "agent fleets," Osmani calls it "the factory model," Cherny just numbers his terminal tabs 1-5. The disagreement is only on shape (cloud fan-out vs. terminal-tab time-multiplex vs. CI-resident roles).

2. **Sandbox-per-agent is now an assumed primitive.** Steinberger's crabbox.sh, Docker's Coding Agent Sandboxes, Modal's ephemeral containers, Cursor's auto-worktrees, and Hykes/Dagger's programmable-pipeline thesis all treat *one disposable execution environment per agent invocation* as table stakes. The arguments have moved on to *what the agent does inside* — repro, before/after video, fuzzing, security review — not whether to isolate.

3. **The new bottleneck is intent quality, not inference cost.** Osmani ("the spec is product thinking made explicit"), Cherny (pattern-to-lint-rule), Dohmke (machine-queryable intent under git), and Yegge (Beads as agent-native memory) all argue the same thing: once tokens are functionally free, specification fidelity becomes the rate-limiting reagent. This is the underside of Steinberger's tweet — he can run 100 codex instances *because* claxsweeper has a tight, falsifiable intent ("link this commit to that 6-month-old issue").

The dissenting note worth flagging: Ronacher and Litt accept the substrate but push back on naive autopilot — Ronacher's "Agent Psychosis" and Litt's "code like a surgeon" mark the audit edge of the cluster.

## Mast implications (own commentary)

The three convergent claims map cleanly onto three mast substrate decisions:

- **Claim 1 (parallelism = unit)** → multi-buffer + `kind: agent` are the load-bearing v0.2 primitives. The whole point is that mast holds N agents simultaneously and the buffer protocol is how the human navigates them.
- **Claim 2 (sandbox-per-agent)** → mast's sandbox capability model is already the right shape (capability flags per Janet invocation). G2 closure converts it from "first slice" to honest cluster-citizen.
- **Claim 3 (intent quality is the bottleneck)** → mast's init.janet + the stax-experiment register together are the "machine-queryable intent" layer for mast itself. The Beads / Entire equivalent for our fleet.

The audit edges (Ronacher / Litt) matter too: mast should NOT hide the failure modes. The audit-log surface (`src/audit.zig`) is the honest "what did the agent fleet actually do" trace — keep it append-only, keep it inspectable, don't auto-summarize away the Type-I errors.
